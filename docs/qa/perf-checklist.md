# Perf Checklist FantasyDisk

Обновлено: 2026-08-16 (FAN-2798). Документ формализует перф-регрессии игры
(FPS, память, время загрузки, размер экспорта). Все метрики измеряются
конкретной командой или панелью Godot 4.7; субъективные формулировки
(«плавно», «быстро», «лагает») в QA-вердиктах запрещены — вердикт без чисел
по этому чек-листу считается неполным.

Целевые значения ниже — предварительные (target); после снятия native
Windows baseline (FAN-2799) они пересчитываются от baseline и обновляются в
этом файле той же картой.

## Референс-сценарии

Каждая метрика снимается на каждом из трёх сценариев, если явно не указано
иное. Сценарии воспроизводимы по команде запуска; окно замера — 60 секунд
устойчивого состояния после завершения загрузки.

| ID | Сценарий | Как воспроизвести |
|---|---|---|
| P1 | Главное меню, idle | `godot --path .` (main scene `scenes/Main.tscn`), не начинать забег, 60 c |
| P2 | Массовый бой, 48 врагов | забег с волной до 48 одновременно живых врагов (массовый уровень как в mass regression 48 enemies из `docs/process/code_quality_and_performance.md`); бо́льшая волна — отдельная карта, не этот чек-лист |
| P3 | Бой с боссом | забег до босса (например `BossBroodMother.tscn`), фаза активного боя, 60 c |

## Метрики, способы измерения и пороги

### M1. FPS (среднее за окно замера и 1% low)

- Снятие (headless не подходит — нужен реальный рендер):
  `godot --path . --print-fps` — движок печатает FPS в stdout каждую секунду;
  собрать вывод за 60 c, среднее и минимум взять арифметически. 1% low —
  минимальное значение среди 1% худших секунд. В редакторе тот же показатель
  виден в отладчике: Monitor `Time/FPS` (`Performance.TIME_FPS`,
  `Performance.get_monitor(Performance.TIME_FPS)`).
- Target: среднее ≥ 60 FPS на P1–P3; 1% low ≥ 45.
- Жёлтый: среднее 45–59 или 1% low 30–44.
- Красный: среднее < 45 или 1% low < 30.

### M2. Статическая память движка (MiB)

- Снятие: Monitor `Memory/Static` (`Performance.MEMORY_STATIC`) в отладчике
  Godot 4.7 (Debugger → Monitors), либо скриптово
  `Performance.get_monitor(Performance.MEMORY_STATIC) / 1048576.0` с выводом
  в лог в конце окна замера. Фиксируется пик за окно.
- Target: P1 ≤ 400 MiB; P2/P3 ≤ 900 MiB (предварительно, до baseline).
- Жёлтый: превышение target на ≤ 20%.
- Красный: превышение target более чем на 20%.

### M3. Число объектов (Object count)

- Снятие: Monitor `Object/Objects` (`Performance.OBJECT_COUNT`) той же
  панелью/скриптом; фиксируется пик за окно на P2 и P3.
- Target: P2 ≤ 5000, P3 ≤ 4000 (предварительно, до baseline).
- Жёлтый: превышение на ≤ 25%.
- Красный: превышение более чем на 25%, либо монотонный рост в пределах
  окна замера (утечка) при любом абсолютном значении.

### M4. Время загрузки до первого кадра (cold start, c)

- Снятие: `godot --path . --verbose 2>&1 | tail -5` — движок печатает
  таймстемпы запуска; время от старта процесса до строки первого кадра.
  Дополнительно: `time godot --path . --quit-after 1` как верхнюю оценку.
  Три прогона, фиксируется медиана. Измеряется только P1.
- Target: медиана ≤ 5 c.
- Жёлтый: 5–8 c.
- Красный: > 8 c.

### M5. Размер Windows-экспорта (MiB)

- Снятие: после сборки
  `stat -f%z FantasyDisk-<version>-windows-setup.exe` (macOS) /
  `ls -l` на Windows, значение делится на 1048576. Метрика снимается на
  релизных сборках, не на P1–P3.
- Target: ≤ 800 MiB.
- Жёлтый: 800–1000 MiB.
- Красный: > 1000 MiB (жёсткий лимит манифеста обновлений — 1 GiB,
  `docs/process/game_updates.md`).

## Правила применения порогов

- Зелёный по всем метрикам — перф-раздел финальной Windows-проверки заполнен
  числами и закрыт.
- Любой жёлтый — вердикт проверки может быть вынесен, но каждая жёлтая
  метрика фиксируется в вердикте с числом и сценарием; PM заводит отдельную
  перф-карту по факту.
- Любой красный — финальная Windows-проверка не проходит; оптимизация —
  отдельной картой, этот чек-лист код не меняет.
- Сравнение с baseline обязательно, если baseline снят: деградация
  относительно baseline на величину порога (M2/M3 — проценты выше, M1/M4/M5 —
  абсолютные) считается жёлтой/красной даже при выполнении target.

## Интеграция в финальную Windows-проверку

Финальная Windows release-проверка (карты `qa_windows`, FomaPC) обязана
содержать раздел «Перф» с числами по всем метрикам M1–M5 этого чек-листа,
снятыми на реальном Windows-устройстве (Mac headless не является
доказательством — см. `docs/process/code_quality_and_performance.md`).
QA-вердикт без заполненного перф-раздела считается неполным и не принимается.
