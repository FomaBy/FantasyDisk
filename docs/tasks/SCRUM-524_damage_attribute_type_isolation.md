# SCRUM-524: Атрибуты урона изолированы по типу (маг качает только маг)

Jira: SCRUM-524 · Роль: backend · Контур: claude · Приоритет: P1 · foma · Эпик: SCRUM-522 (Ребаланс боёвки и прогрессии)
Статус: В работе

## Что и зачем

Игрок прокачивает атрибуты (сила, интеллект, восприятие и т.д.) и должен чётко
понимать билд: «качаю интеллект → растёт магический урон». Сейчас (до этой задачи)
формула урона была «грязной» — у каждого типа урона в базе сидели мелкие splash-вклады
ВСЕХ восьми атрибутов плюс общий `archetype_damage_multiplier`, который зависел опять
же от всех атрибутов и одинаково домножал все три базовых типа. Итог: вложение очка в
интеллект незаметно подталкивало и физический, и звуковой, и DoT-урон. Это ломает
читаемость прогрессии и предпросмотр характеристик (соседние задачи эпика SCRUM-522:
SCRUM-523 — суммарный урон по типам + цветовая кодировка; задача про понятные подсказки/
предпросмотр), и делает баланс непредсказуемым.

Цель: жёсткий инвариант изоляции — прокачка атрибута, владеющего типом урона X, меняет
ТОЛЬКО урон типа X и НИКАК не влияет на остальные типы. Владельцы:
- сила (strength) → физический (`damage`)
- интеллект (intelligence) → магический (`magic_damage`)
- восприятие (perception) + энергия (energy) → звуковой (`sound_wave_damage`)
- знание (knowledge) → периодический / DoT (`dot_damage`)

Ожидаемый результат для игрока: предсказуемая, читаемая прокачка («один атрибут — один
тип урона»); классовый DPS-баланс при этом сохраняется (его теперь полностью держит
классовый budget-множитель, а не размазанные splash-вклады).

прошла QA). Тикет в статусе «В работе». Ниже — что уже сделано и что осталось.

Ключевой файл — `scripts/progression_data.gd`, функция `derived_parameters()`
(объявление на строке 793; блок базовых типов урона — строки ~845–877).

Уже внесённые (незакоммиченные) правки SCRUM-524 (`git diff scripts/progression_data.gd`):
- Функция `_archetype_damage_multiplier(...)` (была ~строки 289–307) **удалена** —
  выпотрошена в комментарий. Она давала `1.0 + bonus`, где bonus зависел от всех
  атрибутов по архетипу оружия (melee/projectile/beam/aoe/summon/aura) и единым
  множителем домножал все три типа базового урона.
- Базы типов урона **очищены от splash-вкладов чужих атрибутов**. Стало:
  - `physical_base := 15.0 * strength / 10.0` (было: + intelligence·0.18 + perception·0.10 + energy·0.12 + knowledge·0.09 + endurance·0.08 + leadership·0.10)
  - `magic_base := 14.0 * intelligence / 10.0` (было: + energy·0.65 + strength·0.16 + agility·0.08 + perception·0.12 + knowledge·0.14 + endurance·0.06 + leadership·0.10)
  - `sound_base := perception + energy` (было: 12.0·(perception+energy)/12.0 + leadership·0.45 + strength·0.08 + agility·0.08 + intelligence·0.09 + knowledge·0.10 + endurance·0.05)
  - `dot_attribute_base := 4.0 + knowledge * 0.65 + dot_damage_flat` (было `universal_dot_base` c вкладами intelligence·0.18 + strength·0.12 + perception·0.10 + energy·0.10 + leadership·0.10)
- Множитель `* archetype_damage_multiplier` **убран** из всех трёх выходов
  (`damage`, `magic_damage`, `sound_wave_damage`) — строки ~864–866.
- `dot_damage` теперь считается от `dot_attribute_base` (строка ~877).

Уже создан (UNTRACKED) изолированный гейт-тест `tests/damage_type_isolation_test.gd`:
- `const ATTRIBUTE_OWNS` фиксирует владельцев типов (strength→damage,
  intelligence→magic_damage, perception/energy→sound_wave_damage, knowledge→dot_damage).
- `_check_attribute_isolation()`: бампит каждый атрибут-владелец на +25, проверяет, что
  свой тип вырос (> EPS) и все прочие типы НЕ изменились (|Δ| ≤ EPS = 0.0001).
- `_check_non_owner_attributes_inert()`: бампит атрибуты без владения типом (ловкость,
  выносливость, лидерство) и проверяет, что НИ ОДИН тип урона не изменился.
- Тест вызывает `PD.derived_parameters(stats, {}, {})` — пустой `weapon_config`, без
  `character_id`, чтобы мерить ЧИСТУЮ формулу типов без классового `_scaled_stat_growth`
  и budget-множителя.

Сопутствующий контекст:
- `damage_multiplier` и `weapon_damage_multiplier` (строки ~813, 820) — общие забеговые/
  оружейные множители; они домножают каждый тип одинаково и НЕ зависят от атрибутов,
  поэтому инвариант изоляции (по атрибутам) не нарушают.
- `universal_damage_flat` (`run_modifiers.damage_flat`) и `dot_damage_flat` —
  забеговые/пассивные плоские бонусы (артефакты/апгрейды), не атрибуты; добавляются ко
  всем типам, но тест проверяет именно АТРИБУТЫ, так что инвариант держится.
- `weapon_archetype()` (строка 168) после удаления множителя НЕ осиротел — он всё ещё
  используется на строках 181, 524, 548, 677. Дополнительно удалять его НЕ нужно
  (иначе сломаются подсказки синергии и budget-расчёт).

Файл `scripts/player.gd`: в рабочем дереве лежит ОТДЕЛЬНАЯ незакоммиченная правка —
это работа SCRUM-523 (константы `DAMAGE_TYPE_*`, `DAMAGE_TYPE_COLORS`,
`damage_type_color()`, маршрутизация типов в `_deal_typed_damage` / `_apply_ultimate_damage` /
`_damage_enemies_in_radius`). К SCRUM-524 player.gd по сути не относится (атрибут→тип
живёт в progression_data.gd), но тикет SCRUM-524 числит player.gd в Files. Менять
player.gd под 524 НЕ требуется — не трогать его правки 523.

  - Урон призывов (`progression_data.gd` ~строки 729–739): `attribute_damage` смешивает

    для саммонер-классов, НЕ базовый типизированный урон, и тест его не покрывает — формально

    (см. шаг 6).
- Зависимость: задача опирается на систему типов урона SCRUM-523 (палитра/маршрутизация
  типов в player.gd). 523 даёт цвет/тип на стороне боя; 524 — изоляцию источника на стороне
  формулы. Они независимы по файлам, но логически парные внутри SCRUM-522.
- EPS в тесте = 0.0001 — формулы чистые (без RNG), детерминированы; ложных красных от
  плавающей точки быть не должно. Если красный — это реальная протечка атрибута.
