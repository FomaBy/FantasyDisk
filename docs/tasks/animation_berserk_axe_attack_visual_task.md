## Context / problem

У Берсерка при атаке `axe` / «Двуручный топор» сейчас визуально читается картинка размаха, а не само оружие. Основная анимация атаки также не выглядит как широкий сектор 180 градусов, хотя текущий gameplay-contract для топора — sweep 180 градусов радиуса 250 px по направлению на ближайшего монстра.

История контекста: SCRUM-728 обновил `vfx_weapon_axe.png`, SCRUM-854/SCRUM-875 закрепили, что точная damage geometry остается outward wedge, а visible sector overlay у меча/топора скрыт. Эта задача — follow-up на читаемость атаки топора, не на баланс.

## Required change

1. Сделать так, чтобы при атаке топором был виден actual weapon/body silhouette двуручного топора, а не только generic slash/crescent.
2. Изменить visible attack sweep для `axe`, чтобы он примерно отражал текущий размер зоны поражения: широкий фронтальный 180-degree arc, короткий радиус около 250 px, направленный по текущему target/aim direction.
3. Не менять damage geometry, cooldown, targeting, DPS, stat scaling и active damage window.
4. Сохранить отличие от меча: sword остается более узким/дальним sweep, axe — широким/коротким cleave.
5. Обновить тесты и документацию по фактическому visual contract.

## Acceptance Criteria

- `axe` attack VFX содержит видимый `WeaponSignatureBody`/weapon layer с топором и не деградирует в один generic crescent slash.
- `axe` visible sweep visually spans broad 180-degree cleave around the attack direction and is scaled to the live `attack_range=250` baseline.
- `sword` and `hammer` visuals keep their existing identity.
- Existing gameplay assertions for Berserk sweep geometry and targeting still pass; no balance/data changes are introduced.
- Focused smokes pass: `tests/attack_vfx_smoke_test.gd`, `tests/animation_smoke_test.gd`, and `tests/runtime_smoke_test.gd` unless blocked by unrelated upstream issues recorded here.
- Docs updated: `docs/design/current_game_state.md`, `docs/design/systems/combat.md`, `docs/design/systems/animation.md` or `docs/design/content_registry.md` as relevant.
