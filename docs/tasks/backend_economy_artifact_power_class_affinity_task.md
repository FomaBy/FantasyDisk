артефакт на текущий класс.

## Требования

### Цены (№2)
1. Все цены магазина поднять в **3-4 раза** (артефакты, предметы, shop_*).
   Согласуй с ценами окна атрибутов из параллельной задачи
   `backend_run_flow_victory_attribute_shop_levelup_button_task.md` —
   общая экономика должна сходиться (денег с боев хватает на осмысленный выбор:
   либо артефакт, либо докачка, не всё сразу).

### Сила артефактов и тиры (№2)
2. Ввести в данные артефактов поле **tier (1-3)**:
   - **Tier 1** (обычный): текущий уровень эффекта x2-3 (например +4..6 к стату);
   - **Tier 2** (редкий): сильный эффект + вторичный бонус (например +15% урона
     И +10% скорости атаки);
   - **Tier 3** (легендарный): **билдообразующий** эффект, меняющий стиль игры
     (например: «каждый 5-й удар — взрыв», «+1 снаряд всем атакам», «HP ниже 30% —
     +50% урона», «саммоны наследуют 30% твоего урона»).
3. Распределить существующие 46 артефактов по тирам (большинство 1, ~трети 2,
   5-8 штук tier 3 с новыми билдообразующими механиками). Новые механики
   реализовать в коде.
4. Цена и редкость появления в магазине/наградах — от тира.
5. Поле tier попадет в иконки (следующая арт-итерация рисует «круче = сильнее») —
   тиры должны быть в данных и задокументированы в content_registry.

### Классовая совместимость (№6)
6. Ввести в данные артефактов поле **class_affinity**: какие классы получают
   полный эффект. Правило вычисления: артефакты, модифицирующие
   класс-специфичные параметры (sound_wave_damage → guitarist, magic_damage →
   dark_mage, melee-механики → berserk), получают соответствующую привязку;
   универсальные (статы, HP, скорость) — для всех.
7. UI везде, где виден артефакт (магазин, награда, HUD-tooltip, пауза, кодекс):
   - эффект не применяется к текущему классу → красная пометка
     **«Не работает на текущем классе»**;
   - применяется частично → желтая пометка **«Работает вполсилы»**;
   - полный эффект → без пометки.
8. Логику частичного эффекта реализовать честно (если артефакт дает 2 бонуса и
   один не для класса — вполсилы) — пометка должна отражать реальный расчет.
