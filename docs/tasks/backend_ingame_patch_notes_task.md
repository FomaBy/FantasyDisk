## Контекст (запрос пользователя, 2026-06-12)
«Заметки об обновлении я хотел бы видеть в каком-то виде в игре, чтобы игрок
мог их прочитать». Источник правды для разработки — CHANGELOG.md, но он
технический; игроку нужны человекочитаемые русские заметки по версиям.

## Требования
1. **Данные:** игровой файл патч-ноутов (например res://data/patch_notes.gd
   или .json): список версий, у каждой — номер, дата, русский заголовок и
   список заметок ДЛЯ ИГРОКА (человеческим языком, без внутренних ID и
   технических терминов — урок SCRUM-148; это НЕ копия CHANGELOG, а его
   игроковая выжимка: новое в игре, изменения баланса, исправления).
   Заполнить ретроспективно: 0.1.0, 0.1.1, 0.1.2, 0.1.3 (из CHANGELOG.md,
   отфильтровав внутреннее) + заготовка 0.1.4 (Unreleased).
2. **Экран «Что нового»:** доступ из главного меню (пункт/кнопка); список
   версий (свежая сверху, развёрнута), прокрутка, Escape-назад. Заголовок
   с номером текущей версии игры (ProjectSettings application/config/version).
3. **Бейдж новой версии:** при первом запуске после обновления (сохранённая
   в user:// последняя просмотренная версия != текущая) — пометка «новое» на
   пункте меню или ненавязчивое уведомление; после открытия экрана пометка
   снимается. БЕЗ модального окна поверх меню при каждом запуске.
4. **Процесс:** дополнен релизный чек-лист (release_versioning.md шаг 11) —
   обновление патч-ноутов входит в блокирующий changelog-гейт. В CHANGELOG.md
   рядом с Unreleased вести и игроковую выжимку не нужно — она живёт в файле
   данных; агенты, закрывающие задачи с видимыми игроку изменениями, могут
   дописывать пункты в секцию 0.1.4 файла данных (укажи это в комментарии
   файла данных).
5. Тесты: данные валидны (версии уникальны, отсортированы, у каждой ≥1
   заметка), экран открывается и содержит фактический текст свежей версии,
   логика бейджа (первый запуск/после просмотра) — с подменой user://-значения.
6. CHANGELOG (Unreleased), current_game_state.md.
