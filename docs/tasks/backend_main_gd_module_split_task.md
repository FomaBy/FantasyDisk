# Back-end Task: Разбиение main.gd На Модули

Статус: выполнена 2026-06-10. main.gd разбит на ui_screens.gd / route_map_screen.gd / combat_director.gd (композиция RefCounted-модулей с ссылкой game вместо отдельных Node, чтобы сохранить контракт main.call(...) для smoke-тестов через делегирующие стабы). main.gd ~620 строк, оба smoke-теста зеленые.
Роль: Back-end
Создано: 2026-06-10

## Проблема

`scripts/main.gd` вырос до ~3300 строк и содержит сразу: главное меню, настройки, выбор персонажа/оружия, маршрутную карту, боевой цикл, спавн/волны/баланс врагов, магазин, события, отдых, level-up, победу/смерть и HUD. Любая задача в любом из этих доменов вынуждена работать с одним гигантским файлом, что увеличивает риск конфликтов и регрессий.

## Цель

Разнести `main.gd` на 3-4 сфокусированных модуля без изменения поведения:

1. `scripts/ui_screens.gd` (или RefCounted-helper): главное меню, настройки, выбор персонажа/оружия, магазин, события, отдых, победа/смерть, level-up UI.
2. `scripts/route_map.gd`: генерация маршрута, connections, отрисовка карты, скролл/pan/drag, tooltips.
3. `scripts/combat_director.gd`: старт/конец боя, спавн, волны, баланс врагов/элиток/боссов, pickups, арена/границы/фон.
4. `main.gd` остается тонким координатором состояний и паузы.

## Требования

- Поведение игры не меняется; рефакторинг строго механический.
- Сохранить систему причин паузы и `player_weapon_effects` cleanup-контракты.
- Texture cache и `_play_sfx`/`_play_music` хелперы переносятся вместе с потребителями или остаются в координаторе.
- После каждого крупного шага запускать оба smoke-теста:
  `runtime_smoke_test.gd` и `animation_smoke_test.gd`.
- Обновить `docs/design/current_game_state.md` (раздел «Проект» и упоминания `scripts/main.gd`) и доменные файлы `docs/design/systems/`, если они существуют.

## Критерий приемки

- `main.gd` < 800 строк.
- Оба smoke-теста зеленые.
- Документация указывает на новые файлы.
