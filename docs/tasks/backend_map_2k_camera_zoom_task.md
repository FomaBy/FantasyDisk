# Задача Для Backend-Агента: Увеличить Карту До 2K И Настроить Камеру

Дата: 2026-06-10

Статус: done 2026-06-11. Результат: боевая арена переведена на `ARENA_SIZE = Vector2(2560, 1440)` и `ARENA_CENTER`, камера использует zoom 1.12 с лимитами по новой карте и не показывает всю арену на 1600x900/2560x1440; фон покрывает 2K-арену, стены/границы/спавн/projectile cleanup используют новые bounds. Runtime smoke test проверяет размер, центр, камеру, фон, спавн и cleanup bounds, проходит.

## Autonomy / Approval

Пользователь заранее одобрил все изменения в рамках этой задачи. Не спрашивай подтверждение на реализацию: внеси изменения, обнови тесты, запусти проверки и обнови документацию. Спрашивать нужно только при реальном блокере, обязательной sandbox/security эскалации или потенциально разрушительном действии вне scope.

## Контекст

Сейчас боевая карта ощущается слишком маленькой: камера показывает слишком большую часть арены, из-за чего теряется чувство пространства, маршрута и маневра. Нужно увеличить размер карты до 2K-формата и немного приблизить камеру, чтобы игрок не видел сразу всю карту.

Под "2K" для текущей задачи использовать целевой размер боевой арены `2560x1440`, так как в игре уже есть поддержка разрешения `2560x1440` в настройках. Если при реализации выяснится, что проект использует другое внутреннее определение 2K, явно зафиксировать это в документации и тестах.

## Цель

Сделать боевую карту больше и настроить камеру так, чтобы:

- карта ощущалась большой;
- игрок видел только часть карты вокруг себя;
- границы карты оставались видимыми при приближении к краям;
- камера не выходила за пределы карты;
- фон, препятствия, спавн монстров, босс-арена и UI корректно работали на новой карте;
- gameplay не ломался на `1600x900`, `1920x1080` и `2560x1440`.

## Scope

Изменить backend/gameplay-часть, связанную с:

- размером арены;
- границами карты;
- лимитами камеры;
- зумом камеры;
- масштабированием фона;
- генерацией препятствий;
- позициями спавна врагов;
- проверками удаления снарядов за пределами арены;
- тестами, которые ожидают старый размер карты.

## Основные Требования

### 1. Размер Карты

Обновить боевую арену до:

```gdscript
ARENA_SIZE = Vector2(2560, 1440)
ARENA_CENTER = ARENA_SIZE * 0.5
```

Не хардкодить старый центр `Vector2(800, 450)` в новых местах. Все системы должны использовать `ARENA_SIZE` и `ARENA_CENTER`.

Проверить все места, где могут быть старые значения:

- `1600`
- `900`
- `800`
- `450`
- camera limits;
- arena walls;
- border drawing;
- background scaling;
- obstacle generation;
- spawn positions;
- projectile cleanup bounds;
- boss spawn;
- player start position.

### 2. Камера

Нужно немного приблизить камеру относительно текущего состояния.

Требование по ощущению:

- на `1600x900` игрок не должен видеть всю карту целиком;
- на `2560x1440` игрок тоже не должен видеть всю карту целиком;
- камера должна показывать комфортную область вокруг персонажа, чтобы было видно угрозы и направление движения, но оставалась причина перемещаться по карте;
- при подходе к границе камера должна плавно ограничиваться лимитами и не показывать пространство за картой.

Технически:

- обновить `Camera2D.zoom`;
- обновить camera limits под `ARENA_SIZE`;
- проверить smoothing, если он есть;
- при паузе camera movement должен замораживаться так же, как сейчас.

### 3. Фон

Фон должен корректно покрывать новую карту:

- фон не должен обрезаться;
- не должно быть пустых зон;
- фон должен масштабироваться или тайлиться под `2560x1440`;
- все текущие фоны должны работать:
  - `stone_garden`
  - `marsh`
  - `dry_road`
  - `meadow`

Если используется один большой Sprite2D, убедиться, что scale рассчитывается от `ARENA_SIZE`, а не от старого размера.

### 4. Границы Карты

Границы должны:

- соответствовать новой карте `2560x1440`;
- быть видимыми;
- иметь корректные collision walls;
- не позволять игроку, наземным монстрам, боссам и снарядам уходить за карту;
- корректно работать при любом поддерживаемом разрешении окна.

### 5. Препятствия

Пересчитать генерацию препятствий под большую карту.

Требования:

- колонн и ям должно быть достаточно для ощущения карты, но не слишком много;
- плотность препятствий не должна стать слишком редкой из-за увеличения размера;
- препятствия не должны блокировать стартовую зону игрока;
- safe radius вокруг старта должен масштабироваться разумно;
- минимальные дистанции между препятствиями должны подходить новой карте;
- летающие монстры по-прежнему должны игнорировать ямы.

Предложение по стартовому балансу:

- колонны: увеличить примерно до `7-12`;
- ямы: увеличить примерно до `5-9`;
- safe radius: `180-220`;
- min obstacle distance: пересмотреть так, чтобы проходы оставались читаемыми.

Если после теста это выглядит плохо, подобрать значения вручную и записать их в документацию.

### 6. Спавн Монстров

Спавн должен использовать новую карту:

- враги появляются по всей карте и с разных сторон;
- не спавнятся слишком близко к игроку;
- не появляются за пределами карты;
- не появляются внутри стен/колонн/ям, если это наземные враги;
- летающие враги могут спавниться над ямами, если это не ломает читаемость;
- активная плотность должна оставаться умеренной.

Важно: увеличение карты не должно сделать бой пустым. Если карта стала больше, а монстры слишком долго бегут до игрока, скорректировать spawn distance/edge spawn logic/active cap/wave pacing.

### 7. Боссы И Элитки

Проверить:

- финальные боссы появляются в корректной позиции;
- boss arena использует новую карту;
- boss patterns не улетают за пределы арены;
- рывки, AoE, radial burst, зоны и призывы не ломаются на большем пространстве;
- элитки корректно спавнятся и преследуют игрока на новой карте.

### 8. Снаряды И Cleanup

Обновить bounds для удаления снарядов:

- enemy projectiles;
- player projectiles;
- magic AoE projectile;
- beam/sound wave visuals, если там есть lifetime/bounds logic.

Нельзя оставлять удаление по старым `1600x900`, иначе снаряды будут исчезать в середине новой карты.
