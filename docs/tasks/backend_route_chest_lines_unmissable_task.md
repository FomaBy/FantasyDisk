# Сундуки-линии на карте: ряды нодов-сундуков, которые нельзя пропустить

Версия: 0.1.8 · Роль: backend · Контур: Claude · Приоритет: P2 · foma · Эпик: Бой, враги, боссы, события
Статус: done · Спринт: 0.1.8
Jira: SCRUM-787
Owner: Backend / Claude
Locked paths: scripts/route_map_screen.gd (chest placement); scripts/main.gd (route-консты chest)

## Что и зачем
Улучшить работу сундука с артефактом. Сейчас на карту ставится **один** сундук в
центральной ветке среднего ряда — игрок легко **пропускает** его, выбрав другой
путь. Нужно сделать сундук **непропускаемым**: оформить сундуки как **целые ряды
(«линии») нодов-сундуков** на карте — ряд, где КАЖДАЯ ветка = сундук. Так какой бы
путь игрок ни выбрал, на этом ряду он обязательно попадёт на сундук и получит
выбор артефакта.

Ожидаемый результат: за акт игрок гарантированно проходит через ≥1 ряд-сундук;
нельзя «промахнуться» мимо награды, выбрав не ту ветку.

## Текущее состояние в коде
`scripts/route_map_screen.gd`:
- `_place_central_chest_node()` (≈307–320): ставит РОВНО 1 chest-нод на midpoint-ряд
  `floor((non_boss_rows-1)*0.5)`, выбирая центральную ветку (избегая шопов,
  ≈323–337). Остальные ветки этого ряда — обычные ноды → сундук пропускаем.
- Открытие сундука: на chest-ноде (≈950–951) вызывается
  `_show_elite_artifact_reward(on_done)` (ui_screens.gd ≈4813–4882) — выбор 1 из 3
  артефактов; награды считает `progression_data.gd:elite_artifact_choices(route_stage,3)`
  (≈1243–1272).
- `_route_node_state()` (≈846–874) помечает выбранную ветку «completed», повторно не
  открыть.
- Тип нода "chest" в `MAP_NODE_DEFINITIONS` (main.gd ≈172) и pool/placement логике.

`scripts/main.gd`: route-консты (ROUTE_STEPS_TO_BOSS и т.д.), node-определения.

## Что сделать — по шагам
1. **Заменить одиночный сундук на «линию сундуков».** Вместо `_place_central_chest_node`
   (1 нод) сделать размещение целого ряда, где ВСЕ ветки = chest-ноды. Реализовать
   helper вроде `_place_chest_line_rows()`: выбрать 1 (минимум) внутренний ряд и
   заполнить все его branch-ноды типом "chest".
2. **Сколько линий.** Гарантировать минимум 1 chest-линию на акт. Сделать число
   настраиваемым константой (напр. `CHEST_LINE_ROWS = 1`, при желании 2 — ранняя и
   поздняя). При 8 нодах (см. [[backend_route_8nodes_act_progression_secret_boss_task]])
   разумно: 1 линия в середине, опционально 2-я ближе к боссу. Значение по умолчанию
   зафиксировать в отчёте.
3. **Непропускаемость.** Поскольку игрок на каждом ряду обязан выбрать одну ветку, а
   все ветки выбранного ряда — сундуки, сундук становится непропускаемым. Проверить,
   что `_assign_route_connections` ведёт в этот ряд из любого предыдущего нода
   (ряд достижим всеми путями).
4. **Не конфликтовать с шопом/алтарём.** Chest-линия занимает весь ряд — этот ряд НЕ
   должен совпадать с обязательным шоп-рядом/алтарём (иначе затрёт гарантированный
   шоп). Выбирать ряд для chest-линии, исключая шоп/алтарь-ряды и START_BATTLE_ONLY_ROWS.
5. **Баланс наград.** Несколько сундуков подряд в линии — это несколько артефактов за
   ряд (по числу веток). Решить: либо каждая ветка-сундук даёт выбор (игрок всё равно
   проходит только ОДНУ ветку ряда → получает 1 сундук — это ок и желаемо), либо
   ограничить. Поскольку игрок выбирает 1 ветку из ряда, он получит ровно 1 сундук с
   ряда — это и есть цель (1 гарантированный сундук на линию). Подтвердить, что не
   выдаётся несколько артефактов за один ряд.
6. **UI/состояние.** Каждый chest-нод открывается через существующий
   `_show_elite_artifact_reward`; пометка «completed» и блокировка повторного захода
   работают как раньше. Проверить отрисовку ряда из одинаковых chest-нодов (иконки,
   подписи) — не должно ломать вёрстку карты.
7. Прогнать `tests/route_chest_artifact_test.gd` (контракт сундука) и runtime smoke;
   при необходимости обновить тест под новую гарантию (есть ≥1 непропускаемый
   chest-ряд; с любого пути игрок проходит сундук).

## Acceptance Criteria

- `tests/route_chest_artifact_test.gd` переписан под новый контракт: ровно
  CHEST_LINE_ROWS полных chest-рядов, каждая ветка ряда = chest (непропускаемость),
