Результат: route map открывается full-screen, стартовые узлы доступны и кликабельны, hover tooltip работает, drag-scroll/pan не вызывает случайный выбор узла, линии тонкие и игнорируют mouse input, карта автоматически фокусирует текущий доступный ряд. Runtime smoke test покрывает start selection, scroll area, drag suppression, route node icons/tooltips/lines и проходит.

## Autonomy / Approval

Пользователь заранее одобрил все изменения в рамках этой задачи. Не спрашивай подтверждение: исправь баг, обнови UI/logic, тесты и документацию. Спрашивать нужно только при реальном блокере, обязательной sandbox/security эскалации или потенциально разрушительном действии вне scope.

## Проблема

При начале игры на маршрутной карте не получается выбрать стартовую точку. Из-за этого забег блокируется сразу после выбора персонажа/оружия.

Дополнительно карта маршрута не помещается на экране. Нужно добавить скроллинг карты или другое удобное решение, чтобы все узлы были доступны и читаемы.

Дополнительное уточнение от пользователя: карта все еще не кликабельна. Не надо загонять карту в маленькую рамку. Она должна быть во весь экран, удобная и понятная. Нужно уменьшить толщину полосок, соединяющих шарики, и добавить проматывание/перетаскивание карты зажатой кнопкой мыши. Игрок должен сразу видеть, что будет впереди, чтобы выбрать лучший путь.

## Главная Цель

Сделать маршрутную карту полностью рабочей:

- игрок может выбрать первый доступный узел после старта;
- клики/hover по стартовым узлам работают стабильно;
- карта открывается как full-screen route map, а не как маленькая карта в рамке;
- карта помещается в UI через удобный drag-scroll/pan;
- все узлы маршрута доступны на `1600x900` и `2560x1440`;
- впереди по маршруту сразу видно достаточно узлов, чтобы игрок мог планировать путь;
- текущая логика ветвления и доступности узлов не ломается.

## Требования К Исправлению Стартового Выбора

Проверить и исправить:

- генерацию первого ряда route nodes;
- `available`/`locked` состояние стартовых узлов;
- обработчики клика по route node;
- hit area / mouse filter / Control layering;
- z-index / порядок UI-ноды, если клики перехватываются другим элементом;
- корректность `_open_route_node` или аналогичной функции;
- переход от выбора оружия к карте;
- reset route state при новом забеге.

Ожидаемое поведение:

1. Игрок выбирает персонажа.
2. Игрок выбирает оружие.
3. Открывается маршрутная карта.
4. Первый ряд доступных узлов визуально подсвечен.
5. Наведение показывает tooltip.
6. Клик по доступному узлу открывает соответствующий encounter.

## Требования К Скроллу Карты

Если карта не помещается на экран, добавить удобный scroll.

Допустимые варианты:

- full-screen route map с drag/pan;
- wheel scroll;
- автоматическое центрирование текущего доступного ряда;
- комбинация этих вариантов.

Минимальные требования:

- на `1600x900` все ряды карты достижимы;
- на `2560x1440` карта выглядит красиво и не ломается;
- карта не должна быть зажата в маленькую рамку или panel;
- route map должна использовать почти весь экран;
- игрок может проматывать карту зажатой кнопкой мыши;
- drag/pan не должен случайно выбирать узел, если игрок именно тащит карту;
- tooltip узлов работает внутри scroll area;
- линии между узлами не обрезаются некрасиво;
- клики по узлам не ломаются после скролла;
- текущий выбранный/доступный ряд легко найти.

## Требования К Full-screen Route Map

Переделать layout карты так, чтобы:

- route map занимала весь доступный экран, кроме аккуратного HUD/кнопок навигации, если они нужны;
- не было ощущения, что карта заперта внутри маленького контейнера;
- узлы были крупными и кликабельными;
- доступные узлы первого ряда были сразу видны;
- следующие ряды маршрута были видны заранее насколько возможно;
- если весь маршрут все равно не помещается, игрок может быстро протянуть карту мышью;
- кнопки/оверлеи не перекрывают узлы и не перехватывают клики;
- mouse filter/z-index/layering настроены так, чтобы узлы реально кликались.

## Требования К Линиям Между Узлами

Уменьшить визуальную толщину соединительных линий между шариками:

- линии должны помогать читать путь, а не доминировать над картой;
- они не должны перекрывать клики по узлам;
- они не должны закрывать иконки, tooltip или текст;
- толщина должна быть аккуратной на `1600x900` и `2560x1440`;
- если есть hover/active state, подсвечивать путь можно цветом/прозрачностью, а не большой жирной полосой.

## UI/UX Требования

- Первый доступный ряд должен быть заметен без угадывания.
- Locked nodes должны визуально отличаться от доступных.
- Если карта прокручивается, игрок должен понимать, что ее можно прокрутить.
- Игрок должен видеть будущие варианты пути достаточно далеко вперед, чтобы выбрать лучший маршрут.
- Full-screen карта должна ощущаться как главный экран выбора пути, а не как маленький виджет.
- Drag-scroll должен быть плавным и предсказуемым.
- Scroll не должен конфликтовать с кнопками меню/HUD.
- Не добавлять лишний текст-инструкцию внутри игры, если можно решить визуально.
