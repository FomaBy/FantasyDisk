# BUG: Атрибут-шоп — кнопки «Обновить»/«Пропустить» уезжают под фолд на 720p

Статус: done
Приоритет: medium
Роль: Back-end (UI)
Версия: 0.1.6
Создано: 2026-06-17
Автор: PM/QA (визуальный ревью рендера на 1280×720)
Jira: SCRUM-467
QA: PASSED (2026-06-17)

## Контекст
Находка из QA-прохода UI на 1280×720. Старая жалоба пользователя на переполнение
окна докачки подтвердилась в конкретном сценарии.

## Причина
Окно докачки (`_show_attribute_shop`) держит карточки опций И кнопки действий
(«Обновить», «Пропустить») ВНУТРИ одного `ScrollContainer`. По умолчанию опций 2
(влезает), но ветка Знаний мета-древа (`attr_extra_options`, SCRUM-150) повышает
число опций до 4–8. На 720p 4 карточки (сетка 2×2) + заголовок + деньги
выталкивают кнопки действий вниз скролла — они уезжают под нижнюю кромку панели.
Технически достижимы прокруткой, но выглядят обрезанными/сломанными, и кнопка
«Обновить» наполовину за экраном.

## Что сделано
`scripts/ui_screens.gd` (`_show_attribute_shop`):
- Добавлен внешний `AttributeShopOuter` (VBox) внутри панели.
- В скролле остаются только заголовок + деньги + карточки опций.
- Кнопки «Обновить»/«Пропустить» вынесены в `AttributeShopActions` ВНЕ скролла,
  закреплены снизу панели — всегда видимы при любом числе опций и высоте окна.
- `_refresh_attribute_shop` ищет кнопки рекурсивным `find_child` — иерархия
  поменялась, поиск работает без правок.

## Проверка (QA — PM, headless-рендер 1280×720)
- Сценарий с 4 опциями (ветка Знаний): обе кнопки «Обновить (… зол.) — осталось N»
  и «Пропустить» полностью видны и закреплены снизу; карточки скроллятся выше.
- `runtime_smoke_test.gd` — PASSED.
