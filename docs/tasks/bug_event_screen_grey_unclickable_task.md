## Симптом (пользователь)
На узле «событие» (event/campfire) экран **серый, ничего нельзя кликнуть** —
опции не выбираются, забег застревает. Game-breaking: нельзя пройти событие.

(Ранее симптом «событие не даёт выбрать опцию / зависает» отмечался и был отнесён
к код-ревью SCRUM-454 — но баг воспроизводится снова, нужен прицельный фикс.)

## Точки входа
- `scripts/ui_screens.gd` → `_show_event_screen(route_node)` (~стр. 4911) — построение
  экрана события и кнопок-опций.
- `scripts/event_data.gd` — определения событий (опции, риск, исходы).
- Поток узла-события в `scripts/main.gd` / роутере (как вызывается `_show_event_screen`).

## Гипотезы корня (проверить)
1. **Кнопки опций не создаются / не подключены** (пустое `route_node`/event definition,
   опции = []), отсюда «серый» пустой экран без кликабельных элементов.
2. **`mouse_filter`** у оверлея/подложки = STOP перехватывает клики, или опции под
   непрозрачным слоем (z-order/перекрытие).
3. **Пауза/оверлей**: экран показан на паузе (`push_pause`) с `process_mode`, при
   котором кнопки не получают ввод.
4. **Дубль текста «Риск:» / переполнение** (ранее отмечалось) — возможно связано с
   некорректной вёрсткой, ломающей зоны кликов.
5. **current_event_definition пуст** при заходе (очищается раньше времени).

## Отчёт worker-2 (2026-06-19)
**Диагноз.** Конструкция экрана события клик-безопасна (Button-карточки, IGNORE-фон/шейд),
а headless emit-тест проходил → баг не в построении кнопок. Реальный симптом «серый,
ничего не кликается» = клики мыши не доходят (HiDPI/слои/платформа) **и нет клавиатурного
fallback'а**: `_show_event_screen` не ставил фокус и не строил focus-chain (в отличие от
level-up). При сбое мыши забег невозможно пройти ничем → застревание.

**Сделано (commit f2628eec):**
- `_show_event_screen`: focus на первую выбираемую опцию + focus-neighbors (лево/право/верх/низ)
  по карточкам и «Назад» → выбор с клавиатуры/геймпада.
- Анти-тупик: пустой/битый `choices` → `_random_event_choices()`; нет доступных опций →
  «Назад» force-enabled как аварийный выход.
- `LevelUpDim` (полноэкранный ColorRect, по умолчанию STOP) → `MOUSE_FILTER_IGNORE`
  (латентный перехватчик кликов на оверлее level-up — «серый экран» при pending level-up).
- `runtime_smoke_test._test_event_route_node_click`: регресс — опции есть, ≥1 выбираемая,
  фокусируемы, экран захватывает фокус на опции.

**Тесты.** Полный `runtime_smoke_test`: event-флоу + новый регресс ПРОХОДЯТ (идут до hero-select).
Единственный fail — pre-existing hero-select-v4 back-button (чужой тикет, не воспроизведён мной).
Изменения изолированы (явный `git add` только своих 2 файлов; вокруг churn skeleton-воркеров).

**Замечание (вне scope).** Решение level-up на узле события уводит на карту маршрута, а не
обратно к событию (`_show_battle_map`, см. `_show_level_up_screen`). Не game-breaking, но
квирк UX — кандидат на отдельную задачу.

**Остаётся для QA.** Визуальная проверка реального клика мышью на сборке (headless не
маршрутизирует реальный GUI-ввод — подтверждено control-пробой на заведомо рабочей кнопке).
