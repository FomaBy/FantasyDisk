# BUG: Форма фидбека не помещается на экране + «Ошибка отправки»

Статус: done
Приоритет: high
Роль: Back-end
Версия: 0.1.6
Создано: 2026-06-17
Автор: PM (находка из плейтеста — скриншот пользователя)
Jira: SCRUM-460
QA: PASSED (2026-06-17)

## Контекст
Пользователь нажал `P` (фидбек) в бою и получил два дефекта на одном экране:
1. **Форма не помещается на экране** — кнопки «Отправить»/«Отмена» уезжали к
   самому нижнему краю / за пределы видимой области.
2. **«Ошибка отправки. Отчет сохранен локально.»** — отправка в Discord-вебхук
   падала, отчёт уходил только в `user://feedback/<ts>/`.

Локальный отчёт (`.../feedback/20260617_094210/`) показал корень обеих проблем.

## Причина
**Ошибка отправки (главное):** скриншот вкладывался в multipart как **PNG в
полном разрешении** (`save_png_to_buffer`). Реальный скрин 1600×970 (на retina —
крупнее) в PNG = **~9.8 МБ**. Лимит загрузки Discord-вебхука на не-бустнутом
сервере ~8–10 МБ; multipart-тело его пробивало → Discord отвечал **HTTP 413
Payload Too Large** → ветка ошибки в `_on_request_completed`. Вебхук жив и
User-Agent на месте (SCRUM-362) — дело было именно в размере вложения.

**Переполнение формы:** панель фиксированной высоты 700px
(`offset_top -350..+350`), а контент VBox (заголовок + поле + превью 300px +
статус + кнопки + отступы) ≈ 720px+ — переполнял панель, кнопки выдавливались
за нижний край. На невысоких экранах усугублялось.

## Что сделано
**`scripts/feedback_reporter.gd` (отправка):**
- Скриншот перед отправкой ужимается: downscale до **1280px по длинной стороне**
  (`Image.resize`, bilinear) + кодирование в **JPG q0.72**
  (`save_jpg_to_buffer`) → ~150–300 КБ вместо ~9.8 МБ. Новый помощник
  `_upload_image_buffer()`; `duplicate()` перед resize, чтобы не мутировать
  оригинал. Вложение: `fantasydisk_feedback.jpg`, `Content-Type: image/jpeg`.
- Локальная копия в `save_local_report()` остаётся полноразмерным PNG (на диске
  лимита нет).
- Сообщение об ошибке теперь содержит реальный код:
  «Ошибка отправки (код 413)…» / «(нет ответа …)» — для будущей диагностики.

**`scripts/ui_screens.gd` (`_show_feedback_overlay`, переполнение):**
- Панель адаптируется под вьюпорт: ширина `clamp(vw-80, 480..940)`, высота
  `clamp(vh-80, 380..780)` — всегда влезает с полями.
- Середина (подсказка + поле ввода + превью скрина) — в `ScrollContainer`
  (вертикальный скролл). Заголовок сверху и статус + кнопки
  «Отправить»/«Отмена» снизу **закреплены и всегда видимы** при любой высоте
  экрана.

## Проверка (QA — PM прогнал лично)
- `tests/runtime_smoke_test.gd` — **PASSED** (включая обновлённые ассерты
  multipart: `UPLOAD_FILENAME`/`image/jpeg`, JPEG-сигнатура в делимитере).
- `tests/feedback_upload_size_test.gd` (новый регресс-гард) — **PASSED**:
  тяжёлый 3200×1940 скрин → JPG **242 КБ**, multipart **243 КБ** (<1 МБ),
  оригинал не мутирован.
- **End-to-end на живом вебхуке**: тот самый 9.4 МБ PNG из локального отчёта
  ужат (sips ≤1280 + JPG) → **302 КБ**, POST на реальный feedback-вебхук вернул
  **HTTP 200** (а не 413); тестовое сообщение удалено (DELETE 204), канал чист.
