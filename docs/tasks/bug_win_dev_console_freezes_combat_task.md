# Bug: Dev console freezes active combat on Windows

Статус: done

## Context / Problem

In the Windows build, opening the in-game developer console during an active match freezes combat. The player and monsters stop moving because the console currently adds a global pause reason and pauses the SceneTree.

## Environment

- Environment: Windows build/player; reproducible from current dev runtime contract.
- Version: active sprint 0.2.0.
- Area: developer console / combat pause handling.

## Steps To Reproduce

1. Start a run and enter any combat match.
2. Open the in-game developer console with the console toggle key.
3. Observe the player, enemies and combat timer while the console remains open.

## Expected Result

The console opens as an overlay and accepts commands, while active combat keeps ticking. Enemies move, the round timer continues, and player movement input still works.

## Actual Result

The console pushes `dev_console` into `pause_reasons`, freezes gameplay state, and sets `SceneTree.paused = true`; combat appears hung until the console closes.

## Acceptance Criteria

- Opening the dev console during active combat does not add a gameplay pause reason and does not pause the SceneTree.
- Console input remains isolated from unrelated hotkeys while the console is open.
- Existing commands still work, including `help`, `spawn`, `kill`, `timer`, `timescale` and `win`.
- Regression coverage verifies that combat continues to tick while the console is open.

## Result

Implemented SCRUM-845 as a focused runtime fix:

- `scripts/dev_console.gd` no longer pushes `dev_console` into gameplay pause reasons when the console opens.
- `close_console()` keeps a legacy cleanup hook that removes a stale `dev_console` pause reason if a hot-reloaded/dev session already had one.
- `tests/dev_console_smoke_test.gd` now verifies that the open console does not pause `SceneTree`, does not add `dev_console`, and active combat continues to tick with player and enemy movement.
- Updated runtime docs in `docs/design/current_game_state.md`, `docs/design/systems/combat.md`, and `docs/design/systems/input_controls.md`.
