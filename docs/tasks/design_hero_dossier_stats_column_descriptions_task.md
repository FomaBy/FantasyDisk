## Source Request

Прямая директива пользователя (чат, 2026-07-08): «на экране выбора персонажа полосы
с характеристиками давай выдадим по правой стороне страницы с описанием. Все
описания всех персонажей надо переписать и сделать более релевантными где будет
понятно и ясно что ожидать от персонажа, сильные и слабые стороны и какие
основные аттрибуты у него».

## Решение

1. Досье HS4DossierFrame: внутренний HBox — слева текстовая колонка (имя,
   описание, сильные/слабые, оружия, идентичность, гайденс) со скроллом,
   справа фикс-колонка из 8 полос характеристик (HS4Stat_* с барами и
   тултипами; ширина ~300·scale, компакт на 720p).
2. Строка «Основные атрибуты: X, Y» — из данных (main_attribute +
   ATTRIBUTE_PRIORITIES), не руками.
3. Переписать тексты 17 классов в progression_data_characters.gd:
   description (чего ожидать от геймплея, 1–2 предложения), strengths,
   weaknesses, идентичности CLASS_MECHANIC_IDENTITIES — ясно, ёмко,
   согласовано с реальными механиками оружий/ульт; тексты оружий не трогать.
4. Кодекс использует те же данные — новые тексты подхватятся автоматически.

## Acceptance Criteria

- [ ] Полосы характеристик — правой колонкой досье на всех вьюпортах теста.
- [ ] Тексты 17 классов: что ожидать / сильные / слабые / основные атрибуты,
      без противоречий с конфигами оружий и ульт.
- [ ] Зелёные: hero_select_pixellab_layout (5 вьюпортов), матрица,
