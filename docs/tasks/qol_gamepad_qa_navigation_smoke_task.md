## Требования
1. `tests/gamepad_full_flow_smoke_test.gd` — headless сквозной сценарий ТОЛЬКО
   синтетическими joypad-событиями (ни одного InputEventKey/Mouse):
   a) главное меню: фокус существует, D-pad ведёт по кнопкам, A открывает выбор героя;
   b) выбор героя: карусель листается, возвышение +/- достижимо, A стартует
      (через выбор оружия/буна если есть — пройти A/D-pad);
   c) в забеге: синтетический стик двигает игрока (позиция меняется), Start
      открывает паузу, B закрывает;
   d) level-up (форсировать доступность через прямой вызов/дебаг-хук как в
      существующих smoke): карточка выбирается D-pad и подтверждается A;
   e) смерть (форсировать): экран смерти управляем, кнопка выхода в меню
      срабатывает по A;
   f) настройки из главного меню: вкладки листаются LB/RB, ребинд-кнопка
      входит в режим прослушивания и принимает JOY-кнопку (round-trip);
   g) отключение геймпада эмулировать нельзя headless — вместо этого проверить
      InputDeviceManager: parse InputEventKey → active_kind()=="keyboard",
      parse JoypadButton → "gamepad" (авто-переключение).
   Тест устойчив к отсутствию реального пада (headless: события синтетические).
2. `docs/process/qa_protocol.md` — новый раздел «Геймпад-чеклист» (обязателен
   для приёмки задач, трогающих UI/ввод): каждый новый/изменённый экран проходим
   с геймпада (фокус на старте, все элементы достижимы, A/B работают), гейт —
   `gamepad_full_flow_smoke_test.gd` зелёный.
3. `docs/design/systems/input_controls.md` — свести финальную карту управления
   (клавиатура+геймпад по всем экшенам и экранам, режимы input_mode) — единый
   справочник (создать/дополнить).
4. Каждый найденный дефект → отдельный bug-тикет Jira (метки foma, bug, p1) с
   шагами воспроизведения; список ключей в результате задачи.
