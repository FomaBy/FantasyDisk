# FAN-3966 — Elementalist and Knight primitive-ratchet repair

Task-owned evidence for the six combat primitive ratchet findings that FAN-3961
classified on the pinned `dev` base `e33bded444e301919dc93c8c9b9f0257e640a1ea`
(tree `9a8401ca1a6dda8a4b446fe45de3fa4f97074426`).

## Defect

Commit `34dc8a932` (FAN-3943, "upgrade three class presentations") added a naked
`Polygon2D` node named `BackdropVeil` to every Elementalist and Knight ultimate
scene as the arena-wide `presence.backdrop = darken` layer. The shared
`UltimateV2PresenceDriver` fits that node to the viewport at runtime, so the
node is a visible full-screen combat primitive. `tests/combat_primitive_ratchet_test.gd`
reports it as three new-scene violations (Elementalist) and a one-count growth
above the allowlisted 4/6/4 (Knight).

## Fix (scene content only)

Each `BackdropVeil` is now a `Sprite2D` over a scene-local 2x2 white
`GradientTexture2D`, the same textured full-screen layer the Berserk, Chemist,
Priest, Ranger, Soldier and Thief packs already ship. The class tint moved to
`modulate` and the authored alpha to `self_modulate`, so the composite colour
`texture * modulate * self_modulate` equals the former `Polygon2D.color`, and
the driver's accessibility scaling (`self_modulate.a *= 0.55 / 0.32`) yields the
same on-screen alpha as before. `z_index = -20` is unchanged. The driver's
existing `Sprite2D` branch fits the sprite to the viewport (`top_level`,
centred, `scale = viewport / texture size`) exactly as the `Polygon2D` branch
did. No script, test, allowlist, manifest, gameplay profile, ID, timing or
flipbook asset changed; no new bitmap was generated and no PixelLab call was
made.

Scene candidate: `ebaf22c113b7e91137eeb1066cc37d322eedab96`
(tree `7d4dd4fd6ecdbfc32cec8e7acc0fcfeb551e1ae5`, ref `agent/fable/6de34bd5a1d4`).

## Live captures (windowed, real run)

`run_live_captures.sh` executed the shipped FAN-3943 certification renderers
(`*_certification_live_capture.gd`, `scenes/Main.tscn` + `_start_combat()`,
shipped HUD and enemies, fixed 60 fps, pinned seeds) against the scene
candidate above, 144 samples per class: 3 weapons x 4 presentation modes x 4
viewports (1152x648, 1280x720, 1920x1080, 2560x1440) x 3 beats. Godot
4.7.stable, gl_compatibility, macOS. Runner log: `logs/live_captures.log`.

Per class under `captures/<class>/`:

- `certification_capture_manifest.json` — the renderer's full 144-sample
  measurement record with the source pin (ref/commit/tree above).
- `sheets/` — the four native-size per-viewport matrix sheets (weapon x mode at
  the active beat) with `sheets_sha256.txt`.
- `native_active_normal/` — the uncropped native frame of every weapon at every
  viewport, normal mode, active beat (12 per class).
- `frames_sha256.txt` — sha256 of all 144 native frames the run produced; the
  other modes/beats were verified through the manifest and not committed to
  keep the repository small.

Measured against the committed FAN-3943 manifests on the base (same seeds,
same 144 sample keys): `backdrop_box_ratio` is 1.0087 on every sample with zero
delta, `effect_box_ratio` and `effect_nodes_drawn` have zero delta on every
sample, `required_nodes_present` and `hud_bands_clear` are true everywhere,
`flash_pixel_ratio` stays <= 0.0049. Only `changed_pixel_ratio` and
`player_contrast` move within live-run noise. The committed docs manifests and
LFS sheets were regenerated by the renderer and then restored with
`git checkout`; they are outside this card's write set.

## Residual risk

The gradient veil is a scene-local procedural texture rather than a drawn
PixelLab frame; this is the same accepted route the other six class packs use
for the darken layer and the standard explicitly allows textured layers. If the
owner wants a painted veil bitmap, that is a separate art card.
