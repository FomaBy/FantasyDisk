## Defect found and fixed: "What's new" badge ignored the fourth part

`scripts/patch_notes_data.gd::_version_greater` compared only
`MAJOR.MINOR.PATCH`. With a `0.3.1.1` entry, `0.3.1.1 > 0.3.1` was false, so a
player updating from 0.3.1 would never get the new-version badge, and
`tests/patch_notes_data_smoke_test.gd` (descending order) failed. It now
compares four parts; a missing or non-numeric part counts as 0, so `0.3.1.0`
equals `0.3.1` and every existing three-part comparison is unchanged. The
updater (`scripts/update_manager.gd`) already handled `X.Y.Z.R` and is not
modified.

Negative control: with the old comparison restored and the new entry kept,
`fan3987_four_component_version_test` fails (`_version_greater(0.3.1.1, 0.3.1)
must be true`, `a player who saw 0.3.1 must get the new-version badge`,
`entries_since(0.3.1) must be exactly [0.3.1.1], got []`) and
`patch_notes_data_smoke_test` fails (`порядок версий нарушен: '0.3.1.1' не >
'0.3.1'`). With the fix both pass.

## Focused test

`tests/fan3987_four_component_version_test.gd` checks:

- updater: `compare_versions("0.3.1", "0.3.1.1") < 0`, the reverse `> 0`,
  `0.3.1.0 == 0.3.1`, `0.3.1.1 < 0.3.1.2`, `0.3.1.1 < 0.3.2`; a `0.3.1.1`
  update manifest (minimum `0.2.2`, canonical release/asset URLs) validates; a
  0.3.1 client is offered it and a 0.3.1.1 client is not;
- badge: exactly one `0.3.1.1` entry, `has_new_since("0.3.1")` true,
  `entries_since("0.3.1")` is exactly `[0.3.1.1]`, `has_new_since("0.3.1.1")`
  false, and the newest note equals the project version;
- main menu: with `0.3.1.1` configured, `MainMenuVersionLabel` reads `v0.3.1.1`.

Results: `focused_suites.txt` (this test plus `patch_notes_composition_test`,
`patch_notes_data_smoke_test`, `patch_notes_smoke_test`, `update_manager_test`,
all PASS).

## Known limitation: Druid Briar Staff capture is at the floor

Three Druid captures of the same code commit `8873160` gave a Briar Staff
minimum player contrast (crowded, 1152×648, active beat) of 0.213, 0.224 and
0.250 against the unchanged 0.25 floor; the capture accepted on `dev` measured
0.258. Seed, beat time, effect box and node counts are identical between runs;
only the live crowd pixels differ (`changed_pixel_ratio` 0.9591–0.9603). The
measurement is not deterministic, and this candidate does not touch combat or
presentation. The floor was not changed. The committed capture and every run
tried for it are listed on the card.
