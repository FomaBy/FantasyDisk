# Перенос чата

## Цель

Перенести рабочий контекст текущего Codex или Claude чата в новый чат без потери состояния: собрать важное, записать Markdown snapshot, создать новый чат, отправить туда snapshot, затем архивировать исходный чат.

## Рабочий порядок

1. Определи платформу и доступные инструменты.
   - Для Codex threads сначала найди thread tools через `tool_search`: `read_thread`, `create_thread`, `send_message_to_thread`, `set_thread_archived`, при необходимости `set_thread_title`.
   - Для Claude chats используй доступный Claude connector/app/thread tool, если он есть в текущем окружении.
   - Если программного доступа к Claude-чату или архивированию нет, сделай Markdown snapshot и честно сообщи, какая часть недоступна.

2. Собери исходный контекст.
   - Предпочитай полный read текущего thread/chat через tool.
   - Если full read недоступен, суммаризируй из видимой истории текущего разговора и явно отметь это в Markdown.
   - Не включай секреты, токены, приватные ключи, cookies, credentials или несущественные логи.

3. Создай Markdown snapshot.
   - Сохрани файл в текущем workspace, если он есть: `docs/chat_transfers/YYYY-MM-DD_HHMM_<slug>.md`.
   - Если workspace неочевиден, используй текущую рабочую директорию: `chat_transfers/YYYY-MM-DD_HHMM_<slug>.md`.
   - Создай директорию при необходимости.
   - Markdown должен быть самостоятельным и пригодным для вставки в новый чат.

4. Создай новый чат/thread.
   - Название: `Перенос: <краткая тема>` или сохраненное название старого чата с префиксом `Перенос:`.
   - Первым сообщением отправь краткую инструкцию: продолжать работу на основе вложенного/вставленного Markdown snapshot, учитывать последние решения и ограничения.
   - Вторым блоком отправь сам Markdown snapshot или ссылку на локальный файл, если thread tool поддерживает файл/URI контекст. Если поддерживается только текст, вставь содержимое snapshot.

5. Проверь, что новый чат получил контекст.
   - Если tool вернул id нового чата, зафиксируй его в исходном финальном ответе и, когда применимо, используй директиву `::created-thread{threadId="..."}`.
   - Если отправка в новый чат не удалась, не архивируй исходный чат; сообщи о частичном результате и пути к Markdown.

6. Архивируй исходный чат только после успешного создания и наполнения нового.
   - Для Codex используй `set_thread_archived`.
   - Для Claude используй соответствующий tool/connector, если доступен.
   - Если архивирование недоступно, сообщи, что переносный файл и новый чат созданы, а закрытие исходного чата нужно выполнить вручную.

## Формат Markdown Snapshot

Используй эту структуру:

```markdown
# Перенос чата: <тема>

- Дата переноса: <YYYY-MM-DD HH:MM TZ>
- Источник: <Codex/Claude, thread/chat id если доступен>
- Новый чат: <id/link если уже создан>
- Ограничение источника: <full thread read | visible history only | connector unavailable>

## Краткое резюме

<5-12 предложений: что происходило, текущая цель, состояние работы>

## Решения и требования

- <важные решения пользователя>
- <неочевидные ограничения>
- <процессные правила, которые нужно сохранить>

## Текущее состояние

- Ветка/репозиторий/проект: <если известно>
- Измененные файлы: <если есть>
- Запущенные команды/проверки: <если есть>
- Открытые процессы/серверы: <если есть>

## Незавершенные задачи

- <следующий конкретный шаг>
- <риски или блокеры>

## Последние важные сообщения

- Пользователь: <смысл последнего запроса>
- Ассистент: <что уже сделано или обещано>

## Инструкция новому чату

Продолжай с этого состояния. Не начинай заново без причины. Уважай ограничения проекта, не теряй решения пользователя, сначала проверь актуальное состояние файлов/инструментов, затем продолжай работу.
```

## Качество Сводки

- Пиши по-русски, если пользователь работал по-русски; сохраняй английские имена команд, файлов и API.
- Не делай transcript dump. Сжимай до решений, состояния, фактов и следующих действий.
- Сохраняй абсолютные пути, branch names, issue ids, thread ids, URLs и названия задач дословно.
- Отмечай неопределенность явно: `не проверено`, `видно только из текущего контекста`, `требует live read`.
- Для кодовых задач добавляй проверку грязного worktree, активной ветки и незавершенных серверов, если это можно безопасно сделать.
- Не закрывай/архивируй источник, пока новый чат не создан и не получил контекст.
